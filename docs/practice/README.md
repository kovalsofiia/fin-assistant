## Структура звіту (з реального прикладу тієї ж кафедри, `~/Downloads/практика_друк.docx`)

були протилежні: вона проходила практику у ФОП Ціптака В.В., де він займався QA). Файл
**не копіювати в репозиторій** (приватні дані іншої особи) — використати лише структуру:

## Відкриті прогалини (не вигадувати, позначити як є або перепитати)

- Хостинг/інфраструктура бази практики (питання 9, 10) — не відповіли; але це для
  Розділу 1 і не потрібне, якщо 1.2 обмежується інструментами з пункту 8.
- Дати практики (з/до), номер наказу, група ФОП практиканта — не збирались, потрібні
  для титульного аркуша й ВСТУПу; взяти з наказу/направлення на практику.
- Щоденник практики — окремий документ, ще не починався.

## Технічні нотатки для збірки .docx (важливо, зекономить час)

- **`pandoc`, `soffice`/LibreOffice відсутні** в цьому середовищі. Читання наявних
  `.docx` робилося вручну: `unzip file.docx -d dir/`, потім regex по
  `<w:t[^>]*>(.*?)</w:t>` у `dir/word/document.xml` (спрацювало надійно для читання,
  без форматування).
- **`docx` (npm) НЕ преінстальований**, попри те, що skill-інструкція каже інше в
  цьому середовищі. Робочий шлях: окрема тека зі своїм `package.json`
  (`npm init -y && npm install docx`), потім писати скрипт і `require('docx')` з
  тієї теки. Встановлення пройшло успішно і швидко (22 пакети).
- **Немає LibreOffice** → неможливо виконати рекомендований skill'ом крок
  `soffice.py --convert-to pdf` для візуальної перевірки. Альтернатива: перевіряти
  структурно (`validate.py` зі skill, XSD-перевірка) і уважно писати XML/docx-js без
  візуального рендеру. Якщо потрібен рендер — попросити користувача відкрити файл
  локально в Word/LibreOffice/Google Docs і показати скрін.
- Дозвіл на використання коду fin-assistant у звіті — **вже отримано** (00b, пункт 16).
