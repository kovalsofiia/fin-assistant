# Протокол оптимізації токенів та роутингу моделей (Model Routing Protocol)

Для мінімізації витрат токенів, уникнення зайвого контексту та максимальної ефективності суворо дотримуйся наступного розподілу ролей та інструментів:

### 1. Claude Haiku — Агент розвідки та читання (Read & Exploration Agent)
* **Зона відповідальності:** Усі операції з читання файлів, пошуку по кодовій базі (`grep`, `glob`), перегляду структури каталогів та аналізу логів.
* **Правило:** Використовуй сабагентів з моделлю **Haiku** для збору інформації. Приймай виключно фінальний саммарі (summary), не завантажуючи сирі логи чи великі шматки коду в головний контекст.

### 2. Claude Sonnet — Агент імплементації (Execution & Coding Agent)
* **Зона відповідальності:** Безпосереднє написання коду, редагування файлів, виконання атомарних кроків реалізації та локальне тестування.
* **Правило:** Пиши код чітко за затвердженим планом, уникаючи зайвих абстракцій та розлогих коментарів.

### 3. Claude Opus — Агент планування та ревю (Planning & Review Agent)
* **Зона відповідальності:** Виключно стадія архітектурного планування (через режим планування/opusplan) перед стартом та фінальне ревю написаного коду/аудит безпеки.
* **Правило:** Залучай важку модель лише на критичних етапах прийняття рішень та перевірки складних блоків.

### Загальні правила економії контексту:
* Ніколи не завантажуй у головний контекст цілі директорії — лише точкові файли через Haiku-сабагентів.
* Заборонено дублювати вміст файлів у відповідях; посилайся лише на зміни та результати.
